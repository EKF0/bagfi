## 3. Workflow (Mandatory — follow this order)

Every agent MUST follow this workflow on every session:

### 3.1 On Resume
1. Read this file (`.AGENTS.md`)
2. Read `docs/progress.md` — know where we left off
3. Read `docs/reports/bags-solana-transition-research.md` — understand the Bags/Solana product direction and constraints
4. Read `docs/reports/agent-skill-stack-research.md` — know the installed/recommended skill stack
5. Read `docs/production-readiness-plan.csv` — see current status and priority
6. Pick the next pending `SOL*` task by priority/dependencies unless the user explicitly asks for a legacy `WS*` task
7. Check the `tasks/` directory only after selecting the roadmap task; create/update a task file if one does not exist

### 3.2 Before Implementing a Task
For **every** task, you MUST run a **Research Phase** first:

```
docs/reports/<task-id>-research.md
```

The research report must answer:
- **Problem understanding**: What exactly needs to be built/changed/fixed?
- **Codebase context**: Find all relevant files, imports, types, APIs
- **Tech & library best practices**: What does the official docs say? Any known gotchas?
- **Alternative approaches**: Are there multiple valid ways? Which is cleanest for this codebase?
- **Risk assessment**: Breaking changes? Edge cases? Regressions?
- **Chosen approach**: One clear recommendation with rationale
- **Implementation plan**: Step-by-step checklist
- **Skill routing**: Which skills from section 5 are required for this task?

> ⚠️ **Do not skip research. Do not implement blindly.**

### 3.3 After Completing a Task
Update **all three** tracking artifacts:

1. **`docs/progress.md`** — Human-readable log of what was done
2. **`docs/production-readiness-plan.csv`** — Update status column (in_progress → completed)
3. **`docs/reports/<task-id>-execution.md`** — Execution report with:
   - Task ID and title
   - What was implemented
   - Commands run and their output (success/failure)
   - Files changed
   - Any blockers or deviations from plan
   - Verification evidence (build passes, lint passes, tests pass)

### 3.4 Status Lifecycle

```
pending → in_progress → completed
                    ↘ blocked (document why)
```

## 6. Research Agent Protocol

For each task, before writing code:

1. Load the required skills from section 5.
2. Gather current docs from primary sources:
   - Bags.fm docs for quote/swap/feed/pool/fee/claim APIs
   - Solana docs for wallet, RPC, simulation, confirmation, and transaction handling
   - Next.js docs for App Router/server route patterns
   - Supabase docs/changelog for schema, RLS, and migrations
3. Write the research report to `docs/reports/<task-id>-research.md`.
4. Only then start implementation.

Key sources by domain:
- **Bags/Solana**: Bags.fm docs, Solana docs, Bags SDK/npm package notes
- **Wallet/Transactions**: Solana Wallet Standard, Solana RPC docs, wallet adapter docs only when needed
- **Supabase**: Supabase JS docs, RLS policy guide
- **Frontend**: Next.js docs, React docs, Vercel guidance
- **Security**: installed security skills plus primary framework/provider docs
- **CI/CD**: GitHub Actions docs, Vercel docs
